# 棋牌项目改造基线

更新时间：2026-08-31

## 项目组成

- `msqp`：Go 服务端，使用 Go workspace 管理 `user`、`gate`、`connector`、`hall`、`game`、`common`、`core`、`framework`。
- `qpClient`：Cocos Creator 客户端，当前项目版本为 2.4.11；已完成 3.x 迁移前的资源加载兼容改造，尚未切换编辑器版本。
- 客户端通信使用 Pomelo 协议；登录、注册等请求通过网关 HTTP，房间和游戏消息通过 connector websocket 转发。

## Cocos 3.8.8 迁移范围

客户端脚本仍大量使用 Cocos 2.x API，已确认需要处理：

- `cc.Class` 组件声明和属性序列化。
- `cc.loader.loadRes`、`loadResDir`、`loadResArray`、`releaseRes` 资源 API。
- 场景和 Prefab 的 2.x 序列化格式。
- `cc.Node`、`cc.Label`、`cc.Sprite` 等组件访问方式。
- Pomelo websocket 客户端和原生平台适配。
- 热更新清单、构建配置以及 Android/iOS/小游戏平台插件。

迁移顺序应保持为：先在 2.4.11 建立行为基线，再通过 Cocos 3.x 迁移工具导入，最后逐模块修复脚本、场景、资源加载和平台构建问题。不能只修改 `project.json` 的版本字段。

业务脚本中的 `cc.loader.loadRes/loadResDir/loadResArray` 已统一改为 `Global.CCHelper` 兼容入口；兼容层内部仍保留 2.4.11 回退 API，并已适配 Cocos 3.x 的资源目录进度/完成回调签名。

共享房间规则中的 `cardsType` 已兼容客户端历史格式（枚举数字、布尔值和 `null`），避免特殊牌型配置在服务端反序列化时失败。

所有已接入玩法在开局时统一递增并同步 `Room.curBureau`，避免跑得快、牛牛、三公和斗公牛结算后局数不变、房间无法按最大局数结束的问题。
